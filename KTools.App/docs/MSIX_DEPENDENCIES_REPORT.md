# 📊 ИТОГОВЫЙ ОТЧЕТ: Исправление доступа при распаковке зависимостей в MSIX

## 🎯 Цель

Исправить ошибку **"Access Denied"** при скачивании и распаковке зависимостей (FFMPEG, MKVToolNix и т.д.) в MSIX приложении.

---

## 🔍 Проблема

**Симптом**: При установке MSIX пакета и попытке скачать зависимости возникает ошибка:
```
UnauthorizedAccessException: 
"Нет прав доступа для создания папки 'C:\Program Files\Windows...\KTools\bin\...'"
```

**Причина**: Приложение пыталось сохранять зависимости в папке установки (`Program Files\KTools\bin\`), которая защищена от записи для MSIX приложений.

---

## ✅ Решение

### Файл 1: `KTools.App/Core/PathManager.cs`

**Изменения**:
- Метод `GetBinDirectory()`: добавлена проверка типа приложения (MSIX или обычное)
- Метод `GetSettingsDirectory()`: аналогично обновлена для согласованности

**Логика**:
```csharp
// Определяем является ли приложение MSIX
string? packageName = Environment.GetEnvironmentVariable("PACKAGE_NAME");
bool isMsix = !string.IsNullOrEmpty(packageName);

if (isMsix)
{
	// MSIX → используем LocalAppData (есть права на запись)
	return Path.Combine(LocalAppData, "KTools", "bin");
}
else
{
	// Обычное приложение → используем папку установки (как раньше)
	return Path.Combine(BaseDir, "bin");
}
```

### Файл 2: `KTools.App/Core/DependencyManager.cs`

**Изменения**:
- Добавлена обработка `UnauthorizedAccessException` в методе `InstallDependencyAsync()`
- Добавлено информативное сообщение об ошибке

**Логика**:
```csharp
try
{
	Directory.CreateDirectory(destinationFolder);
}
catch (UnauthorizedAccessException ex)
{
	// Перехватываем ошибку доступа и сообщаем пользователю
	string errMsg = "Нет прав доступа для создания папки...";
	LogService.Instance.Error(errMsg, "DependencyManager");
	InstallFinished?.Invoke(key, false, errMsg);
	return;
}
```

## 🔄 Как это работает теперь

### При запуске MSIX приложения:

```
1. App.xaml.cs инициализирует приложение
   ↓
2. DependencyManager создается
   ↓
3. PathManager.GetBinDirectory() вызывается
   ↓
4. Проверяется Environment.GetEnvironmentVariable("PACKAGE_NAME")
   ├─ Если != null → MSIX → LocalAppData\KTools\bin
   └─ Если null → обычное → BaseDir\bin
   ↓
5. Все операции используют выбранную папку
```

### При скачивании зависимости:

```
InstallDependencyAsync("ffmpeg")
  ├─ Скачать архив → Path.GetTempPath() (всегда доступно)
  ├─ Создать папку → destinationFolder (MSIX: LocalAppData, обычное: BaseDir)
  ├─ ✅ Если ошибка доступа → перехватить и сообщить
  ├─ Распаковать архив → tar.exe
  └─ Верифицировать → проверить файл exists
```

## 💾 Детали реализации

### Определение MSIX

```csharp
string? packageName = Environment.GetEnvironmentVariable("PACKAGE_NAME");
bool isMsix = !string.IsNullOrEmpty(packageName);
```

**Почему это работает:**
- MSIX приложения автоматически устанавливают переменную `PACKAGE_NAME`
- Обычные приложения не имеют этой переменной
- Это стандартный способ определения MSIX в .NET

### Выбор папки

**Для MSIX**:
```
C:\Users\[CurrentUser]\AppData\Local\KTools\
├── bin\              ← зависимости (FFMPEG, MKVToolNix, DEE, QAAC)
├── logs\             ← логи приложения
└── config.json       ← конфигурация
```

**Для обычного приложения**:
```
[ApplicationFolder]\
├── bin\              ← зависимости (как раньше)
├── logs\             ← логи (если нет прав на запись)
└── config.json       ← конфигурация (если нет прав на запись)
```

## 🆘 Возможные проблемы

### Проблема: Файлы не загружаются после исправления

**Решение**:
1. Проверить что MSIX пакет создан с новым кодом
2. Проверить что `PACKAGE_NAME` установлена (см. логи)
3. Проверить права на запись в `LocalAppData\KTools`

### Проблема: Приложение не видит старые зависимости

**Решение**:
- Старые зависимости остаются в `Program Files\KTools\bin\`
- Метод поиска `GetBinaryPath()` всё ещё проверяет обе папки
- Или можно вручную скопировать файлы в новую папку
