# Блок 01: Оркестрация `OnLaunched` — до первого кадра только необходимое

## Цель

К моменту `window.Activate()` на UI-потоке выполняются только: логгер,
чтение настроек, создание окна и начальная навигация. Все остальное уходит
в фон после первого кадра.

## Контекст

Сейчас `KTools.App/App.xaml.cs:OnLaunched` синхронно делает до/вокруг
`Activate()`: полный снепшот системы (включая опрос всех дисков),
`ScriptRegistry` (блок 03 разгрузит изнутри, здесь его не трогать),
`ShellIntegration.NeedsUpdate/Register`, разбор `PendingArgs` с ретраями через
`Thread.Sleep`, запуск `FileSystemWatcher`. Каждый пункт дешев на SSD
и дорог на HDD (спящие диски, seek, AV-скан).

## Зона правок (владение блока)

- Только `KTools.App/App.xaml.cs`.
- Разрешенные регионы: `OnLaunched` (порядок вызовов), `ProcessPendingArgsFiles`,
  `StartArgsWatcher` (+ приватные хелперы этих методов при нужде).
- ЗАПРЕЩЕНО трогать: строку запуска `HardwareCapabilityCache.InitializeAsync`
  (~строка 960, владение блока 05) — обойти ее, не двигать; конструкторы
  сервисов; `AppStartupPipeline`.

## Шаги

1. Вызов `ISystemInfoService.LogSystemCharacteristics()` перенести в фон после
   `window.Activate()` (`Task.Run`, отмена при закрытии). Когда блок 02 добавит
   раздельные методы fast/extended — переключить вызов на них; до тех пор
   работает с существующим методом (совместимость обоих вариантов обязательна,
   чтобы блоки сливались в любом порядке).
2. `ShellIntegration.NeedsUpdate/Register` (регион ~строк 963–1003) — в фон
   после `Activate()`, best-effort с try/catch (уже есть, сохранить).
3. `ProcessPendingArgsFiles()` — убрать синхронный вызов из `OnLaunched`;
   запускать в фоне после `Activate()`. Внутри заменить `Thread.Sleep` в цикле
   ретраев на `await Task.Delay` с отменой; ограничить число попыток.
4. `StartArgsWatcher`: из обработчика `Created` убрать `Thread.Sleep(50)`,
   добавить дебаунс (~200 мс) и диспетч обработки в фон.
5. Порядок в `OnLaunched` зафиксировать комментарием: логгер → настройки →
   окно → `Activate()` → фон (система, shell, pending-args, watcher).

## Инварианты

- `AppStartupPipeline` (логгер → хендлеры → настройки) не менять.
- Поведение single-instance/pending-args сохранить: аргументы второго запуска
  обязаны доставляться, просто асинхронно.
- Никаких новых блокировок UI-потока: `await` без `.Result/.Wait()`.

## Приемка

- Время от запуска до первого кадра на HDD не зависит от: числа дисков,
  наличия спящих/сетевых дисков, мусора в папке `PendingArgs`,
  включенной интеграции контекстного меню.
- Аргументы командной строки/контекстного меню доходят до открытого окна.

## Проверка

- `dotnet build KTools.sln -c Debug -p:Platform=x64`
- `dotnet test KTools.sln -c Debug -p:Platform=x64`
- Ручная: холодный старт с отключенным вторым диском vs подключенным спящим;
  ETW-трейс (`tools/perf/Trace-Startup.ps1`): до первого кадра нет обращений
  к другим дискам и записи в реестр shell.
